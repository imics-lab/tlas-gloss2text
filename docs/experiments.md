# TLAS Experiments and Results

## 1. Experimental Design

### 1.1 Three Evaluation Paradigms

We evaluate TLAS under three complementary paradigms that test different aspects of the streaming translation problem:

**E1 — Sentence-level evaluation (ASLG-PC12)**: Isolated sentences with synthetic uniform timestamps. Policies operate within known sentence boundaries. This measures linguistic quality in a controlled setting but neutralizes the temporal signal (uniform timestamps → pause_score ≈ 0).

**E2 — Continuous stream discourse evaluation**: The primary experiment. Multi-sentence discourse groups are fed as one continuous gloss stream with realistic per-gloss timestamps. Policies must discover sentence boundaries themselves. This is the setting where TLAS's temporal-linguistic fusion provides its advantage.

**E3 — Real stream file evaluation**: Qualitative demonstration on manually timestamped monologue and dialog stream files. Validates that TLAS works on real (non-synthetic) timing patterns.

### 1.2 Rationale for E2 as Primary

In E1, all policies operate within known sentence boundaries and synthetic uniform timestamps (~450ms per gloss) neutralize the TPD. The pause_score remains near 0, and TLAS degenerates to max_lag triggering every 6 glosses. This artificially penalizes TLAS relative to baselines.

In E2, inter-sentence gaps of 2–7 seconds provide clear temporal signal. The proactive timeout mechanism fires at gaps exceeding ~1.1 seconds (EMA × 2.5), enabling TLAS to segment sentences cleanly. Baselines (Wait-k, TransLLaMa) cannot exploit this signal and fragment across boundaries or produce one large blob.

## 2. Datasets

### 2.1 ASLG-PC12

- **Source**: HuggingFace (`achrafothman/aslg_pc12`)
- **Size**: ~87,000 ASL gloss–English parallel pairs
- **Domain**: European Parliament proceedings
- **Preprocessing**: Filter to ≥3 gloss tokens and ≥3 English tokens; glosses uppercased; text lowercased
- **Split**: Shuffled with seed=42; train (50,000) / val (10,000) / test (10,000)
- **Use**: Primary training data for T5 fine-tuning; E1 sentence-level evaluation

### 2.2 SIGNUM

- **Source**: Local files (`data/signum_sents_anno_eng.txt`, `data/signum_sents_trans_eng.txt`)
- **Size**: 779 German Sign Language sentence pairs
- **Domain**: Everyday topics (weather, travel, family)
- **Format**: Tab-separated ID and gloss/text per line
- **Use**: Training augmentation for T5 (cross-domain vocabulary exposure); cross-dataset evaluation

### 2.3 Synthetic Discourse Dataset

- **File**: `data/synthetic_discourse.jsonl` (1,400 groups, ~2 MB)
- **Generation**: Gemini LLM with vocabulary constraints (≥80% root coverage from ASLG-PC12 + SIGNUM)
- **Types**: Monologue (~40%), deaf-deaf dialog (~30%), deaf-hearing dialog (~30%)
- **Timestamps**: Per-gloss arrival times generated by Gemini LLM with rule-based validation
  - Within-sentence: 300–650ms per sign
  - Between-sentence: 1500–7000ms depending on discourse context
- **Split**: Lines 1–200 = test (200 groups, 888 deaf sentences); lines 201–1400 = train (~5,234 context pairs)
- **Deaf-hearing groups**: Hearing turns have `text` only (no gloss); contribute to context but not to translation targets

### 2.4 Stream Files (E3)

| File | Type | Tokens | Sentences | Description |
|------|------|--------|-----------|-------------|
| `monologue1-gloss_stream.txt` | Monologue | 108 | 20 | Single signer narrative |
| `monologue2-gloss_stream.txt` | Monologue | ~80 | 14 | Single signer narrative |
| `dialog3-stream.txt` | Dialog | ~150 | ~30 | Bidirectional deaf-hearing |

Format: `[HH:MM:SS.mmm] Speaker (Type): SINGLE_TOKEN`

Inter-sentence gaps in stream files: typically 2–7 seconds.

## 3. Training

### 3.1 T5 Fine-Tuning

**Base model**: T5-base (250M parameters) downloaded fresh from HuggingFace.

**Training data composition**:
- Standard gloss↔text pairs from ASLG-PC12 (bidirectional)
- TransLLaMa-style streaming examples: early prefixes → `<WAIT>`; mid prefixes → partial translation
- Discourse context pairs from synthetic_discourse.jsonl (sliding window, 3 prior turns)
- SIGNUM cross-domain pairs

**Configuration** (`config/discourse_fresh.yaml`):

| Parameter | Value |
|-----------|-------|
| Epochs | 5 |
| Per-device batch size | 8 |
| Gradient accumulation steps | 4 |
| Effective batch size | 32 |
| Learning rate | 5 × 10⁻⁵ |
| Warmup ratio | 0.1 |
| Weight decay | 0.01 |
| Label smoothing | 0.1 |
| Precision | FP16 |
| Special tokens | `<WAIT>` (ID 32100) |

**Output**: `models/t5_base_discourse/final/`

### 3.2 LRE Head Training

**Procedure**:
1. Generate semantic oracle labels: translate every gloss prefix with frozen T5, compute ROUGE-L against reference, enforce monotonicity
2. Train LRE head (197K parameters) with MSE loss on oracle labels
3. T5 encoder frozen throughout

**Configuration**:

| Parameter | Value |
|-----------|-------|
| Optimizer | AdamW |
| Learning rate | 10⁻³ |
| Loss function | MSE |
| Batch size | 64 |
| Epochs | 5 |
| Best model selection | Validation loss |

**Training results** (v2, matched to discourse encoder):
- Epoch 1: train=0.0277, val=0.0225
- Epoch 4: train=0.0181, val=0.0197 (best)
- Epoch 5: train=0.0173, val=0.0202

**Output**: `models/t5_base_discourse/final/lre_head.pt` (773 KB)

## 4. Policies Under Evaluation

### 4.1 External Baselines (Published Methods)

| Policy | Reference | Mechanism | API calls per step |
|--------|-----------|-----------|-------------------|
| **Batch** | — | Oracle: translate complete sentence | 0 (decision) + 1 (translation) |
| **Wait-k** (k=3) | Ma et al., 2019 | Fixed 3-token delay; non-overlapping windows | 0 (no decision needed) |
| **TransLLaMa** | Agostinelli et al., 2023 | Model outputs `<WAIT>` or translation | 1 (WAIT check) + 1 (translation on WRITE) |

**Batch (oracle)**: Used only in E2 as the upper bound. Translates each ground-truth sentence independently with full discourse context. Represents the best possible segmentation.

**Batch (non-oracle)**: Accumulates the entire discourse group as one blob, translates once. In E2, this produces a single long translation that aligns poorly with individual reference sentences.

### 4.2 Ablations (This Work)

| Policy | Signal | Mechanism | API calls per step |
|--------|--------|-----------|-------------------|
| **LSG** | KL/Confidence (T5) or LRE (API) | KL divergence + confidence threshold | 0 (standalone LRE) |
| **TLAS-linguistic** | LRE only | AFG with w_t=0, w_l=1 | 0 (standalone LRE) |
| **TLAS-temporal** | TPD only | AFG with w_t=1, w_l=0 | 0 (no LRE needed) |
| **TLAS** | TPD + LRE | Full AFG fusion (w_t=0.4, w_l=0.6) | 0 (standalone LRE) |

**LSG (Local Scoring Gate)**: Our own prior approach using raw T5 encoder heuristics (KL divergence between current and baseline next-token distributions). For API backends, falls back to the standalone LRE. Included to quantify the improvement from the trained LRE over naive encoder statistics. LSG is **not** a published external method.

**Context isolation**: In E2, only TLAS variants receive discourse context (context_window=3). All baselines and LSG receive context_window=0. This isolates the segmentation effect from the context effect, ensuring that TLAS's advantage comes from better segmentation rather than from receiving additional context information.

## 5. Translation Backends

### 5.1 Backend Configurations

| Backend | Model | Readiness Scoring | Translation |
|---------|-------|-------------------|-------------|
| **T5** | t5-base fine-tuned (`models/t5_base_discourse/final/`) | Native LRE head on encoder states | Local, beam search (4 beams) |
| **Gemini** | gemini-3.1-flash-lite-preview | Standalone T5 encoder + LRE (~5ms) | API (rate-limited) |
| **Ollama** | gpt-oss-32k:latest | Standalone T5 encoder + LRE (~5ms) | Local API (localhost:11434) |

### 5.2 Standalone LRE for API Backends

For non-T5 backends, the T5 encoder and LRE head are loaded as a local singleton module. This provides consistent readiness scoring across all backends without per-gloss API calls. The standalone module:
1. Tokenizes glosses with the T5 tokenizer
2. Encodes through the T5 encoder (frozen)
3. Passes encoder hidden states through the trained LRE head
4. Returns readiness_score in [0, 1]

Latency: ~5ms per call on GPU (negligible compared to API translation latency).

## 6. Evaluation Metrics

### 6.1 Translation Quality

| Metric | Implementation | Range | Description |
|--------|---------------|-------|-------------|
| **BLEU-4** | sacrebleu corpus_bleu | [0, 100] | Primary metric; n-gram precision with brevity penalty |
| **ROUGE-L** | rouge-score (F-measure) | [0, 1] | Longest common subsequence overlap |
| **SBERT** | all-mpnet-base-v2 cosine similarity | [-1, 1] | Sentence-level semantic similarity |
| **chrF++** | sacrebleu (char_order=6, word_order=2) | [0, 100] | Character + word n-gram F-score |

### 6.2 Streaming Latency

| Metric | Formula | Description |
|--------|---------|-------------|
| **Average Lagging (AL)** | AL = (1/\|Y\|) Σ_t [g(t) − (t−1)] | Source tokens read before output token *t*, averaged (Ma et al., 2019) |
| **LAAL** | AL × (source_len / target_len) | Length-Adaptive AL; normalizes for length ratio |
| **Retention** | BLEU_policy / BLEU_batch | Fraction of batch quality retained by streaming |

### 6.3 Position-Based BLEU (E2 Only)

In E2, each reference sentence has a position within its discourse group (0 = first, 1 = second, etc.). BLEU is computed separately per position bucket {0, 1, 2, 3, 4+} to reveal whether policies maintain quality throughout a conversation or degrade over time.

### 6.4 Metric Selection Rationale

- **SBERT over BERTScore**: Token-level BERTScore (roberta-large) produced near-identical scores (0.98x) across all policies, failing to discriminate. SBERT provides a much wider range (0.20–0.78) and better captures sentence-level semantic similarity.
- **chrF++**: Robust to morphological variation and less sensitive to tokenization choices than BLEU. The word_order=2 variant (chrF++) adds word bigrams to the character n-gram base.
- **Retention rate**: Normalizes BLEU by the oracle (batch) score, enabling fair comparison across backends that may have different absolute quality levels.

## 7. E2 — Continuous Stream Discourse Evaluation

### 7.1 Evaluation Procedure

For each discourse group in the test split (200 groups, 888 deaf sentences):

1. **Build event stream**: Convert the group into a flat sequence of `(timestamp, gloss_token, sentence_index)` events using pre-annotated per-gloss timestamps.

2. **Feed to policy**: Events are fed one by one to the policy's `step()` method, simulating real-time gloss arrival.

3. **Proactive timeout** (TLAS only): Before processing each new gloss, check if the gap since the last gloss exceeds `EMA × pause_multiplier`. If so, translate the buffer immediately and flush — simulating idle timeout in a real-time system.

4. **Reactive decision**: After feeding the gloss, check the policy's READ/WRITE decision. On WRITE, translate the buffer and record the segment.

5. **Segment alignment**: After processing all events, align policy-produced segments to reference sentences by majority voting on sentence indices. Each segment is assigned to the reference sentence that contributed the majority of its glosses.

6. **Metric computation**: Compute BLEU, ROUGE-L, SBERT, and chrF++ between aligned hypotheses and references. Compute BLEU by position.

### 7.2 Oracle Baseline

The Batch (oracle) baseline translates each ground-truth sentence independently with full discourse context. This represents perfect segmentation + full context, the theoretical ceiling for streaming policies.

### 7.3 Segmentation Behavior

The key differentiation in E2 comes from how policies segment the continuous stream:

- **TLAS (temporal)**: Proactive timeout fires at inter-sentence gaps (2–7s >> 1.1s threshold). Buffer is translated and flushed during each pause. Result: one segment per sentence (near-perfect segmentation).

- **Wait-k**: Translates every 3 glosses regardless of boundaries. A 7-gloss sentence produces 2–3 fragments. Some fragments span sentence boundaries. Result: many small, incoherent segments.

- **TransLLaMa**: Asks the model at each step whether to wait or translate. More adaptive than Wait-k but lacks temporal signal. May trigger prematurely or miss boundaries.

- **Batch (non-oracle)**: Waits for end-of-group (final gloss). Translates the entire group as one blob. Result: one long translation with almost no overlap to individual references.

### 8.8 Timestamp Robustness Evaluation (T5, E2, TLAS Variants Only)

200 discourse groups, 888 sentences. Three timestamp conditions:

- **Realistic**: LLM-generated per-gloss timestamps (2–7s inter-sentence gaps)
- **Uniform**: Constant 450ms gaps throughout — no inter-sentence pause signal
- **Noisy**: Realistic timestamps + Gaussian jitter (σ=500ms) with monotonicity enforcement — simulates vision module latency variance

Only TLAS variants evaluated (baselines and LSG excluded; Batch oracle included as ceiling).

| Policy | Realistic | Uniform | Noisy |
|--------|-----------|---------|-------|
| **Batch (oracle)** ↑ | **24.49** | **24.49** | **24.49** |
| TLAS-temporal | **23.70** | 15.61 | 10.07 |
| TLAS | 21.51 | 16.68 | 11.53 |
| TLAS-linguistic | 17.18 | **17.09** | **17.18** |

ROUGE-L:

| Policy | Realistic | Uniform | Noisy |
|--------|-----------|---------|-------|
| **Batch (oracle)** ↑ | **0.5929** | **0.5929** | **0.5929** |
| TLAS-temporal | **0.5636** | 0.4409 | 0.3913 |
| TLAS | 0.5359 | 0.4690 | 0.4176 |
| TLAS-linguistic | 0.4741 | **0.4744** | **0.4741** |

**Key findings**:

1. **TLAS-linguistic is timestamp-invariant**: BLEU varies less than 0.1 points across all three conditions (17.18 → 17.09 → 17.18), confirming that it relies solely on the LRE linguistic signal and max_lag fallback with zero sensitivity to timestamp quality.

2. **TLAS-temporal degrades catastrophically**: BLEU drops 57% from realistic to noisy (23.70 → 10.07). The TPD EMA is corrupted by jitter, causing premature or delayed segmentation.

3. **Crossing point at uniform timestamps**: Under uniform timing, TLAS-linguistic overtakes TLAS-temporal (17.09 vs 15.61). Under noisy timing, the gap widens substantially (17.18 vs 10.07).

4. **Full TLAS degrades gracefully**: TLAS full (21.51 → 16.68 → 11.53) declines less than temporal-only because the LRE provides a stabilizing floor, but still drops 46% under noisy conditions due to the temporal weight (w_t=0.4) pulling the combined score toward unreliable TPD outputs.

**Experimental design note**: In LINGUISTIC_ONLY mode, the proactive timeout mechanism is disabled (the timeout relies on TPD's EMA, which is a temporal signal). TLAS-linguistic decisions are therefore driven entirely by the LRE readiness score and the AFG max_lag safety net (6 glosses). This ensures the ablation measures pure linguistic readiness.

## 9. Analysis and Key Findings

### 9.1 Central Result: TLAS Achieves Near-Oracle Segmentation

In E2 (continuous stream), TLAS-temporal achieves **96.8% retention** on T5 and **90.7% retention** on Gemini. This means the temporal signal alone recovers nearly all translation quality compared to oracle segmentation.

### 9.2 Two-Tier Separation

E2 results show a clear two-tier separation across all four metrics:

- **TLAS cluster** (TLAS, TLAS-temporal, TLAS-linguistic): 18–24 BLEU
- **Baseline cluster** (Batch, Wait-k, TransLLaMa, LSG): 1–15 BLEU

The gap is consistent across BLEU, ROUGE-L, SBERT, and chrF++, confirming it is not an artifact of any single metric.

### 9.3 Position-Based BLEU: The Smoking Gun

The BLEU-by-position analysis reveals *why* baselines fail in E2:

**Baselines degrade catastrophically from position 1 onward:**
- Batch: 6.77 → 2.14 → 0.28 → 0.01 → 0.00
- Wait-k: 4.68 → 2.03 → 1.83 → 0.84 → 0.27

**TLAS variants maintain quality across all positions:**
- TLAS-temporal: 20.10 → 25.52 → 21.67 → 27.03 → 21.28

This confirms the **cross-boundary fragmentation hypothesis**: baselines cannot discover sentence boundaries in continuous streams, producing fragments that span boundaries. These fragments are meaningless to the translation model, and quality collapses. TLAS's temporal signal enables clean segmentation, maintaining quality throughout the conversation.

### 9.4 Temporal vs. Linguistic Under Timestamp Degradation

When temporal signal is reliable (realistic LLM timestamps, 2–7s inter-sentence gaps):

- TLAS-temporal (23.70) > TLAS (21.51) > TLAS-linguistic (17.18)

The temporal signal alone is sufficient for near-perfect segmentation. Adding the LRE (full TLAS) slightly hurts, suggesting the v2 LRE introduces minor noise in the discourse setting.

However, this ranking **reverses** when timestamps become unreliable. See Section 8.8 for the full timestamp robustness evaluation. The short version:

| Condition | TLAS-linguistic | TLAS-temporal | Δ (ling − temp) |
|-----------|----------------|---------------|-----------------|
| Realistic | 17.18 | **23.70** | −6.52 |
| Uniform | **17.09** | 15.61 | +1.48 |
| Noisy | **17.18** | 10.07 | +7.11 |

TLAS-linguistic is remarkably stable across all three conditions (18.11 → 17.09 → 17.18), while TLAS-temporal collapses under degraded timestamps (23.70 → 15.61 → 10.07). This motivates TLAS-linguistic as a **robustness fallback** for deployment scenarios with imperfect vision module timing.

### 9.5 Backend Comparison

The E2 results are remarkably consistent across backends:
- Both T5 and Gemini yield oracle BLEU ≈ 24 and TLAS-temporal BLEU ≈ 22–24
- The relative ranking of policies is identical across backends
- Baselines benefit more from stronger LLMs (Gemini Wait-k=11.49 vs T5 Wait-k=1.86) because LLMs can "complete" fragments more coherently, but the gap to TLAS remains large

Ollama (gpt-oss-32k) has a lower ceiling (oracle BLEU=12.53), but preliminary results show the same two-tier pattern.

### 9.6 Wait-k and TransLLaMa Fragmentation

Wait-k with k=3 translates every 3 glosses. In a 5-sentence group with ~25 total glosses, this produces ~8 fragments. Some fragments span sentence boundaries (e.g., last gloss of sentence 1 + first 2 glosses of sentence 2). These cross-boundary fragments are particularly harmful: the translation model treats them as coherent input and produces hallucinated completions.

TransLLaMa is more adaptive but still lacks temporal information. With T5, the `<WAIT>` token behavior is learned but imperfect. With Gemini, the WAIT-or-translate prompt works better (12.54 BLEU) but still cannot match temporal segmentation.

### 9.7 LSG vs. LRE

LSG (KL divergence + confidence) achieves 6.43 BLEU on T5 E2, while TLAS-linguistic (trained LRE) achieves 18.11 BLEU. This 2.8× improvement demonstrates the benefit of learning readiness from semantic oracle labels versus using raw encoder statistics.

On Gemini E2, the gap narrows (LSG=14.88 vs TLAS-linguistic=18.86) because both use the standalone LRE scorer for API backends — LSG falls back to LRE when it cannot access T5 internals.

### 9.8 Cross-Domain Generalization (SIGNUM)

On SIGNUM (completely different domain and vocabulary from training data), TLAS achieves 99.1% retention. Low absolute BLEU (3.47) is expected due to domain shift, but the retention pattern confirms that TLAS's segmentation decisions generalize across domains.

## 10. Experimental Controls and Reproducibility

### 10.1 Context Isolation

In E2, context_window is set to 0 for all baselines and LSG. Only TLAS variants receive discourse context (window=3). This ensures TLAS's advantage comes from segmentation quality, not from receiving additional contextual information that baselines do not.

### 10.2 Incremental Results

The evaluation harness saves results incrementally to JSON after each policy completes. If interrupted, the evaluation can be resumed without re-running completed policies. Results are keyed by policy name in the JSON file.

### 10.3 Seed Control

Random operations are seeded (seed=42) for ASLG-PC12 shuffling, synthetic timestamp generation, and data splitting. The discourse test split is positional (first 200 lines), not random.

### 10.4 Metric Implementation

All metrics use standard library implementations:
- BLEU: sacrebleu (corpus-level)
- ROUGE: rouge-score (sentence-level, averaged)
- SBERT: sentence-transformers all-mpnet-base-v2
- chrF++: sacrebleu (char_order=6, word_order=2, beta=2)

### 10.5 Hardware

Experiments run on NVIDIA DGX Spark with GB10 GPU (CUDA 13.0). T5 inference runs on GPU. SBERT scoring runs on GPU. API backends use rate-limited HTTP calls.
